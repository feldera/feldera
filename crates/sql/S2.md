# Experimental circuit file boundaries

The Java compiler has hidden `--write-s2`/`--read-s2` and
`--write-s3`/`--read-s3` flags for spikes 1 and 2. These use version 4 of an
unstable subset protocol, separate from version-1 observation dumps and public
Gen-2 JSON. They do not establish a production hybrid boundary.

The disposable [Rust multiset experiment](multiset-probe/README.md) also rewrites
these files for 50 fixed programs, applying its restricted dead-code pass before
Java resumes S2 or S3. This checks a Rust transformation at the file boundary;
the rest of the optimizer remains in Java.

Run each side in an isolated JVM. Use the same compiler build, runtime identity,
and effective options, including `--gen2`, `-i`, optimization level, streaming
and correlation diagnostics, and whether the output uses multiple crates.
For example, from `sql-to-dbsp-compiler` after building the compiler:

```sh
java -jar SQL-compiler/target/sql2dbsp-jar-with-dependencies.jar \
  -i --dump-producer-commit "$compiler_revision" --dump-runtime-abi "$runtime_revision" \
  --input_circuit --noRust --write-s2 program.s2.json program.sql

java -jar SQL-compiler/target/sql2dbsp-jar-with-dependencies.jar \
  -i --dump-producer-commit "$compiler_revision" --dump-runtime-abi "$runtime_revision" \
  --read-s2 --js schema.json -o program.rs program.s2.json
```

For an S3 file, replace `--input_circuit --write-s2` with `--write-s3`, then use
`--read-s3` on import. S2 runs the complete optimizer. S3 runs the hash computation
and existing output writers on the decoded optimized circuit. Saved hash
annotations are replaced, so equal saved ids cannot conceal different preimages.
A regression corrupts every saved hash before import and checks the recomputed
preimages and ids against uninterrupted compilation.

Export refuses to overwrite a file. Import checks the version, stage,
compiler/runtime identities, effective options, and supported operators and
declarations. It rejects duplicate JSON keys, trailing content, and files larger
than 64 MiB. These are local spike limits, not approved G7/G10 budgets or
fuzzing evidence. S2 and S3 files cannot be interchanged.

The explicit operator allowlists live in `CircuitReplay`. They include all 30
top-level operator classes observed at S2 and all 57 observed at S3 in the 8,571
exported cases. Both boundaries support struct and function declarations; S3
also supports static and comparator declarations. Other forms fail explicitly.
An allowlist entry is not evidence of a correct decoder: coverage selections
and full-corpus replay test their behavior separately.

The files carry:

- Schema JSON, SET values and declaration positions, source text and API line
  boundaries, and diagnostics with their continuation and suppression state.
- Pending nonexistent-view LATENESS checks, with view spelling and source range.
  S2 stops before these checks; resumed compilation reports them after the
  optimizer, preserving diagnostic order and warning promotion. S3 has no
  pending checks. This state was introduced in version 3.
- View property key and value ranges. Version 4 rejects earlier files, which
  dropped these ranges and changed the provenance of generated emit_final
  windows. Public Gen-2 properties and persistent hash inputs retain their
  string-only representation.
- Column/default positions, view SQL, tuple field names, and exact source
  presence and positions, including the absence of a position.
- Relational identities, final/partial references, sequences, table-read sets,
  shared provenance nodes, diagnostic SQL names, and view origins.
- The generated-variable counter and markers for built-in type singletons.
  Ordinary type definitions remain distinct; references retain sharing.
- The compiler-owned row-weight variable, including its link into the circuit,
  and each aggregate list's cached empty-result tuple. Later passes reuse these
  objects; reconstructing equal values can change graph sharing or variable binding.
- Calcite-plan JSON and provenance links into it. The executable Calcite plans
  are not reconstructed. Plan/dataflow JSON is compared semantically; formatting
  can differ after import.

`ProgramSchema` supplies the schema operations needed after lowering without a
Calcite type factory. `RelReference` separates live planner objects from the
identity and diagnostic information used by circuit passes. Imported references
use the same existing provenance composition algorithms as live references.
Streaming warnings, correlation diagnostics, plans, and dataflow output work on
the tested subset.

`scripts/validate_s2_replay.py` runs eight focused programs in both modes, using
three fresh JVMs per case: direct compilation, export, and import. Its default S2
mode compares every S2/S4/S3 graph with the strict Rust comparator. `--stage S3`
compares final S3 graphs and validates the single-observation capture. The
`--final-s3` comparator permits different local sequence numbers; options,
runtime identity, graph sharing, annotations, metadata and positions still match.
The Java workflow runs both experiments and retains their artifacts.

`scripts/run_seam_inventory.py` inventories every exported case at both stages
and selects cases by uncovered operator/declaration forms before replay. Its
report distinguishes instance counts from case counts and retains failures.
`scripts/run_s2_corpus.py --stage S3` checks the selected population's final
graphs, schemas, full diagnostics, generated artifacts, and recomputed hash
inputs. Its separate `final-s3-v1` contract cannot stand in for S2's complete
optimizer-prefix contract. Neither mode executes the generated program.

Both focused experiments pass: S2 compares **6,174 observations in 48 JVMs**;
S3 compares **16 final graphs in another 48 JVMs**. Schemas, diagnostics, Rust and
stubs match exactly where applicable; plan and dataflow JSON match semantically.
Certificates are [s2-provenance-replay.json](evidence/s2-provenance-replay.json)
and [s3-tail-replay.json](evidence/s3-tail-replay.json). Separate CLI tests compare
single-file and multi-crate workspaces byte for byte, and hash callbacks compare
actual preimages. These tests do not execute the generated programs.

`scripts/run_s2_corpus.py INPUT.jsonl OUTPUT_DIR` runs the guarded corpus
experiment with two fresh JVMs and records input, compiler and comparator
digests. It accepts the same build-identity/classpath arguments as the focused
driver. `--source-class org.dbsp.sqlCompiler.compiler.sql.simple.CastTests`
selects every case of that class before either run. CI uses this selection;
failed processes keep partial files without a completion certificate.

The underlying Java corpus runner accepts `replay-s2` in place of `capture` or `baseline`. It
preserves source options and SQL submission boundaries, exports S2, imports into
a fresh compiler, and records the usual fingerprints. Unsupported cases fail
and retain their S2 file. Compare against `capture` with `scripts/determinism.py compare`. For Gen-2 seam comparisons, give **both** JVMs
`-Dfeldera.determinism.seamArtifacts=true`. This explicit `seam-v1` contract uses
the strict graph canonicalizer for circuit JSON and parsed JSON for dataflow,
retaining raw-byte fingerprints as a separate metric. Rust files and hash
preimages remain byte-exact. The default `exact-v1` repeated-capture experiment
continues to compare all artifact bytes. Comparison rejects different contracts.

The earlier 50-case classic result remains in
[s2-corpus-replay.json](evidence/s2-corpus-replay.json). Expanding to all 167
CastTests cases exposed a missing `originalStruct` field on tuple types, which
made ROW-to-VARIANT lowering fail after import. The internal codec now preserves
that field. Strict S3 comparison also exposed constructors inheriting a child's
position where the original node had none; the codec now restores absence.

Generated-name state and VARIANT representation remain JVM-global in Java.
The importer restores their saved state; ordinary SQL compilation and the
three-JVM determinism harness do not reset their allocators. Concurrent imports
in one process are outside this experimental API's contract.

At this point the seam still needed broader operator coverage, full-corpus
validation, the Rust subset port, isolated S4 checkpoints and independent
review. The [P0 checklist](P0.md#exit-checklist) records subsequent results.

The corpus runner now declares `dataflow_contract: all-engines-v1` and requires
a dataflow artifact for classic output as well as Gen-2. Dataflow fingerprints
compare parsed JSON in both engines; generated Rust still requires byte equality. Older completed runs
retain their narrower `gen2-only-v1` contract; their classic generated-Rust
comparisons did not check dataflow provenance. The comparator refuses to compare
runs with different dataflow contracts or to accept missing required artifacts.

`scripts/summarize_seam_corpus.py OUTPUT.json --input PREPARED.jsonl
--shard RUN_DIR` verifies a complete sharded population. Repeat `--input` and
`--shard` for partitioned input and output. It rechecks the captured fingerprints,
input records and digests, requires matching build/stage identities and the
`all-engines-v1` dataflow contract, and rejects missing or overlapping cases.
The certificate covers the supplied prepared population; it does not approve
cases excluded during corpus export or establish runtime equivalence.
