# Binder prototype and early typing

Option H builds all 28,960 accepted function plans in the generated spike 5
manifest and matches their result name and complete scalar type. The other
13,920 probes are rejected by both planners. H uses the common Feldera
inference rules in `ScalarUDFImpl::return_field_from_args` and a
`TypePlanner::plan_type_field` hook. This measures the result and verdict
projection. C0 diagnostic parity, full C1a, C9 and the held-out comparison
remain open. The prototype has no FRel exporter for general queries. A uses the Feldera
parser directly and builds a typed scan and projection with resolved ordinals,
explicit coercions, literal payloads and expression spans. A and H agree with
Java on the same **42,880 function probes** and **16,384 arithmetic probes**.
A's negative results in these populations are all type rejections. Its
later structured diagnostics match Java on all 59,264 generated cases,
including 19,488 errors and 824 warnings. The Rust probe retains the
projection's full token range for errors and warnings about the projection.
This scope keeps the generated single projection over a direct table.
[Binder C0 evidence](evidence/a-binder-c0.json)

For D1d, 16 INTEGER set fixtures passed through the existing S1 relation
decoder and the real Feldera runtime, paired with the Java baseline. The
32 generated Rust tests passed in the Linux ARM64 devcontainer. DISTINCT and
ALL, three versus two copies including NULL, reversed sides, empty inputs and
nested operations all have explicit expected bags. The candidate keeps
Intersect and Minus in the relation graph before Java lowering. The narrow
adapter handles constant leaves, so this result covers the stated set-operation
fixtures and leaves general query conversion in the main H experiment.

Quantified array comparisons bypass the registry and the binary-expression
hook. `plan_any_op` constructs `array_has`, `array_min` and `array_max`.
`plan_all_op` constructs those functions plus `cardinality` and
`array_position`, and adds its own NULL/empty CASE. H needs to retain the
quantified AST or patch these paths. EXTRACT, array literals, POSITION and
SUBSTRING have distinct hooks and still need Feldera implementations.

One concrete early rejection is
`VALUES (CAST('a' AS CHAR(1))), (CAST('bb' AS CHAR(5)))`. Preserving the two
widths lets the scalar signatures see them, but stock `infer_data` then raises
`Inconsistent metadata across values list`. Dropping metadata would prevent
that rejection while losing the fields that the spike is designed to test.
A `RelationPlanner` now intercepts derived two-row, one-column VALUES.
It plans each child, computes the common Feldera type, and constructs the
relation with explicit casts to that type. Six focused programs agree with
Java, including mixed CHAR widths, DECIMAL widening, typed NULLs and
nested calls. The stock top-level VALUES witness still rejects.

The generated and directed cases establish the measured subset. The held-out
baseline below records what remained incomplete when D1 stopped.

## Shared corpus split and baseline reach

The [frozen split](evidence/d1-heldout-baseline.json) uses 8,571 reviewed classic
exports and 1,333 Java diagnostic captures. It assigns a test method and all
methods with identical program text to the same partition. The method-group
hash fixes the split before additional binder work. The archive preserves
submission order, batch metadata, Java diagnostics, and the available Java
schemas. The current binder command accepts one SQL string per record, so
negative diagnostic inputs are assembled from their captured SQL submissions.

The held-out partition contains 1,466 original exports and 97 Java diagnostic
cases. A emitted zero projections. H emitted three result fields, all for
original exports. There were 18 development cases beyond both probes' manifest
limit. The denominator retains them. Both binaries received the same 9,886
available manifest records. A ran on Linux ARM64 and H ran on macOS ARM64.

The run measures reach into the original corpus. The probes still lack
equivalent FRel trees and exact C0 and C1a on the common scope. Section 3.4's
incomplete-evidence rule therefore applies.

## Decision on 2026-11-18

The plan owner chose to stop D1 under the incomplete-evidence rule in
PLAN.md §3.4 and keep A as the planning assumption. The parity floor remains
unevaluated on equivalent FRel coverage. The D1d result remains valid for its
16 executable fixtures.
