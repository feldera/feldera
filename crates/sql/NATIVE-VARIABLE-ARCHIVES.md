# Native decimal and string archive increment

This bounded experiment extends the native archive encoder to actual decimal
and string rows from the frozen [ten-program inventory](NATIVE-PROGRAMS.md).
It also restores a real DBSP nullable-decimal checkpoint into a different live
key type whose serializer emits native-generated bytes. It does not complete
N1 or N2. No production DBSP interface changes are involved.

## Types and representation

The encoder now writes both limbs of an i128 decimal mantissa. Actual
`feldera_fxp::Fixed<P,S>` values validate precision and supply the mantissas; the
encoder does not infer precision, rescale values, or implement decimal arithmetic.
The complete row bytes are compared against rkyv for these inventory types:

| Type ID prefix | Actual archived row | Inventory use |
|---|---|---|
| `28310a2273f8` | `Tup1<Option<Fixed<6,2>>>` | decimal-window index key |
| `a60aa7a1c0cb` | `Tup1<Option<Fixed<38,10>>>` | numeric index value |
| `293544e012d7` | `Tup2<Option<i32>,Option<Fixed<38,10>>>` | numeric input row |
| `d4c66cb739c2` | `Tup4<i32,i64,Fixed<38,10>,Fixed<38,10>>` | numeric expected output row |
| `277867b07403` | `Tup1<Option<SqlString>>` | Unicode string input row |

Additional single-field `Fixed<38,20>` and required-string rows
are stress fixtures, not additional inventory row-shape coverage. Scale 20 is
required by the multiplication program's scalar types; testing its mantissa
does not execute the multiplication program.

The string encoder targets the pinned rkyv 0.7.45 little-endian `size_64`
representation used by the actual `feldera_sqllib::SqlString`. Rust plans checked
allocation offsets; Cranelift code writes every payload byte, inline length,
relative offset, and NULL tag. Values of at most 15 bytes are inline. Longer
UTF-8 payloads precede the aligned root. No process pointer is persisted.
Each returned slice owns a complete independently relocatable archive.

The current encoder supports up to eight string and eight fixed-width slots
in a checked root layout. It writes multiple relative string offsets and
merges validated fixed-width fields into each root. The exact selected shapes
include mixed strings and integers, aligned decimal rows, empty rows, unsigned
time fields and the nullable nested address. Bounds reject malformed
descriptors, required NULLs, incorrect widths, narrowing, excessive batches and
oversized strings before native calls. All 29 explicit stored shapes from
the frozen selection now have byte-equality and relocation evidence.

## Implicit aggregate and rolling layouts

The selected linear aggregates pass concrete weights into DBSP's generic
factory. The nullable SUM uses `Tup3<i64, i64, i64>` for its sum, non-null count
and group-presence count. The global COUNT and COUNT DISTINCT use
`Tup2<Tup2<i128, i64>, Tup2<i64, i64>>`. The incremental aggregate builds
weighted input and trace batches, a set of keys awaiting aggregation,
optional accumulator and output values, vectors of keyed upserts and a timed
output trace. Keep the output absence tag distinct from a present nullable
SQL result.
[Selected aggregate builder](native-dbsp-probe/src/aggregate.rs) ·
[Aggregate factories](../dbsp/src/operator/dynamic/aggregate.rs) ·
[Upsert factories](../dbsp/src/operator/dynamic/upsert.rs)

The selected rolling COUNT uses `Tup0` for its partition key, `u64` for
ordered time and `Tup1<i64>` for its accumulator. The factories keep
`Tup2<u64, V>` in the partitioned input trace, use `Tup2<Prefix<u64>, TreeNode<u64, A>>`
for the file-backed radix tree, and produce `Tup2<u64, Option<O>>` in the
partitioned result. The radix updater also allocates child pointers, node
updates and vectors of updates.

Three fixed-width internal payload shapes match the full rkyv archive and
decode after unloading the writer. Nine fixtures cover zero and signed
weights, a wide count, and absent versus zero rolling results. The archive
retains both earlier build failures. One encountered a full devcontainer
filesystem, and one required a scalar sample for the optional one-field
tuple because its generated archive type lacks `Default`.

The fixed-width encoder now accepts a shared discriminant for all fields of
an optional accumulator tuple. It validates that the fields are all present
or all absent before any native call. `Option<Tup3<i64, i64, i64>>` matches
rkyv for absent, zero and nonzero values. Both input APIs reject partially
present tuples. All 28 integer, decimal and string archive tests pass on the
updated build, as do both focused Clippy checks.

The frozen nullable SUM and COUNT DISTINCT pipelines now restore real
file-backed accumulator traces in both directions between classic Rust and
the native encoder. Both graphs retain their original persistent IDs and
runtime fingerprint. Each relinked native pipeline also reads its previous
checkpoint after the first library instance is dropped. The tests use forced
spill and compare signed SQL outputs and error streams with an uninterrupted
classic pipeline.

The wrappers instantiate two fixed accumulator layouts. The rolling COUNT
radix-tree row also matches rkyv byte for byte in five fixtures covering
both optional child slots, prefix widths and accumulator boundaries.
The test obtains the offsets from the actual DBSP archive type and decodes
the resulting bytes after unloading the encoder. The deployed rolling
probe still uses the existing Rust radix-tree writer. Descriptor-backed
trace construction and general checkpoint metadata compatibility remain
open.

## Checks and actual state restoration

Archive tests check complete byte equality before typed access, decoding from
aligned copies, archived/live ordering and Xxh3 hash agreement. Decimal cases
include precision extrema, fractional steps and mixed NULL masks. String cases
include empty values, embedded NUL, non-BMP Unicode, 15/16-byte transitions and
long payloads. Archive storage remains usable after unloading its native writer.

The decimal state test uses the actual `Tup1<Option<Fixed<6,2>>>` key. An original
Rust tuple-key join spills and checkpoints. A different live key type retains
an encoder owner and uses a prebuilt transparent archived adapter for exactly
that row layout. Its serializer writes the native bytes. Existing DBSP
`Data`/factory machinery then restores the original checkpoint without changing
topology fingerprints or bypassing storage metadata. Four subsequent
transactions check NULL duplicates, decimal extrema and retractions against
explicit bags and an uninterrupted oracle. The test writes a native checkpoint,
destroys the runtime and all strong code owners, recompiles, restores again, and
checks a fifth post-restore transaction. Both spill thresholds are zero.

Actual checkpoint files are retained. Their metadata contains original paths;
the copied evidence has not been separately relocated and restored. Serialization,
deserialization and archived-search counters prove these paths ran, but their
exact counts are not stable requirements. The initial retained run observed
36 writes, 97 reads and 11 archived/live searches.

The live decimal adapter stores an actual typed tuple plus its encoder owner.
It is not a generic runtime row factory. Its `SizeOf` implementation omits the
private native library allocation; no memory-size or performance claim follows.
The nullable VARCHAR encoder also has a bounded live key adapter, verified
through persistent DBSP interchange on four workers.
[String checkpoint evidence](evidence/native-persistent-string-state.json)

## Key and program coverage boundaries

Full-width normalized keys preserve order for the actual nullable DECIMAL(6,2)
key under all four direction and NULL-placement policies. Mantissas share each
field's fixed scale.

A mixed encoding adds UTF-8 text beside decimal and BIGINT. It preserves
embedded NULs and prevents prefix strings from consuming the next field in
byte order. The runtime-type test checks 1,742,400 pairs against
`SqlString`, `Fixed<6, 2>` and BIGINT across 64 ordering policies. The
[sort and merge measurement](BENCHMARKS.md#mixed-text-decimal-and-bigint-keys)
finds an encoding-inclusive loss in all six synthetic configurations. All
five selected index-key types now have additional paired measurements.
[Index-key certificate](evidence/native-corpus-index-keys.json)

`native_coverage.py` joins the exact ten frozen IDs to all 21 steps, 208 explicit
types and 18 operator classes. Every operator has a source-backed runtime
starting point. The emitted ledger checks the complete denominator and includes
expression-function paths, exact input/output row IDs, weighted-step semantics
and explicit index keys. It records verified C7 execution for all ten cases.
[Native execution certificate](evidence/native-json-execution.json)

The selected rolling circuit restores classic state with native serialization
on both nullable DECIMAL join keys. The witness preserves the generated
operators, persistent IDs, and remaining concrete state types. A reusable
descriptor-backed factory graph and coverage of all implicit state layouts
remain open. [Rolling checkpoint certificate](evidence/native-rolling-checkpoint.json)

The [certificate](evidence/native-variable-archives.json) pins 28 DBSP tests,
12 native batch/key tests, five ledger tests, Clippy and formatting results.
It retains actual checkpoint bytes, five new executables and all local Rust
dependency sources. The [implementation ledger](evidence/native-coverage-ledger.json)
records these five additional row shapes alongside the six prior integer shapes.
