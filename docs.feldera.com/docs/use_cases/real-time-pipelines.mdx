# Real-time pipelines

A batch job computes all of its results again on each run, so the results are old and the compute cost increases with the data. A Feldera pipeline runs the same SQL incrementally. When the input changes, Feldera updates only the results that the change affects, from the raw tables to the final views.

## Why Feldera

- **The SQL you already run.** Feldera evaluates [full SQL](/sql) incrementally, including joins, aggregates, window functions, subqueries and [recursion](/sql/recursion).
- **History and live data in one pipeline.** Load a snapshot from [Delta Lake](/connectors/sources/delta) or [Iceberg](/connectors/sources/iceberg), then continue on changes from [Kafka](/connectors/sources/kafka), [Debezium](/connectors/sources/debezium) or [PostgreSQL CDC](/connectors/sources/postgresql-cdc).
- **Correct results.** Each view always equals the result of its query on all of the input. With [fault tolerance](/pipelines/fault-tolerance-overview), a pipeline continues from where it stopped after a crash.
