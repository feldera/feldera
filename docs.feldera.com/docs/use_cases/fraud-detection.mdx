# Fraud detection

A fraud model is only as good as its features. With Feldera, you write the features once in SQL. The same queries compute training data from history and compute features for each live transaction, so training and scoring always agree.

## Why Feldera

- **One set of queries.** Train on [Delta Lake](/connectors/sources/delta) history and score live transactions from [Kafka](/connectors/sources/kafka) with the same SQL. You change only the connectors. The features are identical in training and inference, no matter how complex the queries.
- **Exact features for each transaction.** Joins and [rolling aggregates](/tutorials/time-series) are updated incrementally, so each feature vector is correct when the transaction arrives.
- **Models in the loop.** A model can [read its inputs from a view and write its scores to a table](/use_cases/model_scoring/), so the pipeline measures its accuracy while it runs.
